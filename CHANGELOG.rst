busy-beaver-rs 项目更新日志
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

2026-05-12
==========

v0.4 数组引擎
-------------
- 将状态转移表从 ``HashMap<(State, Symbol), Transition>`` 改为数组形式的 ``TransitionTable``。
- 新增规则索引编码：``index = state_id * symbol_count + symbol``，机器执行时通过数组下标查找转移规则。
- 生成器不再维护 ``RuleKey`` 列表，也不再对 ``HashMap`` 执行 ``insert`` / ``remove`` 回溯。
- 生成器改为按规则槽位顺序向 ``Vec<Transition>`` 执行 ``push`` / ``pop``，叶子节点生成数组转移表。
- 纸带从 ``HashMap<i64, Symbol>`` 改为双向 ``Vec<Symbol>``：非负坐标和负坐标分别按需扩展。
- 移除运行路径上的 ``RuleKey`` 构造和哈希查找成本，为后续候选机器 ID 编码与并行搜索打基础。
- 命令行打印冠军组时默认只展示前 5 台机器，保留完整冠军机器数量统计，避免输出过长。
- 新增数组转移表索引测试和双向纸带读写测试。
- 保留 v0.3 的 ``Σ(n)`` / ``S(n)`` 冠军组语义，BB(2) 回归测试继续验证 ``Σ(2)=4``、``S(2)=6``。

v0.3 结果语义拆分
-----------------
- 将单一 ``best_table`` 结果拆分为两类冠军组：``sigma_champions`` 和 ``step_champions``。
- ``sigma_champions`` 表示 ``Σ(n)`` 语义，记录停机时纸带上 ``1`` 数量最多的机器组。
- ``step_champions`` 表示 ``S(n)`` 语义，记录运行步数最多且正常停机的机器组。
- 新增 ``ChampionGroup``，统一记录冠军组的 ``best_ones``、``best_steps`` 和对应状态转移表集合。
- 命令行输出改为分别打印 ``Sigma(n) 最多 1 冠军组`` 和 ``S(n) 最长停机步数冠军组``。
- 搜索结果新增运行耗时统计，最终结果中输出本次搜索总耗时。
- ``SearchConfig`` 新增 ``progress_interval``，支持搜索过程中周期性输出已搜索机器数、停机数、达到步数上限数和耗时。
- 命令行新增第三个可选参数用于控制进度输出间隔，传入 ``0`` 可关闭进度输出。
- 新增 BB(2) 回归测试，验证 ``Σ(2)=4`` 和 ``S(2)=6`` 的结果语义仍然正确。

2026-05-04
==========

BB(2) 单机模拟器原型
--------------------
- 新增基础 Busy Beaver / 图灵机模拟流程，支持从空白纸带、初始状态 ``A`` 和读写头位置 ``0`` 开始逐步执行状态转移。
- 使用 ``State``、``Move``、``Transition`` 和 ``Machine`` 建模状态、移动方向、转移规则和机器本体。
- 使用 ``HashMap<(State, u8), Transition>`` 表示状态转移表，支持通过 ``当前状态 + 当前符号`` 查找下一步规则。
- 使用 ``HashMap<i64, u8>`` 表示稀疏纸带，未写入的位置默认读取为 ``0``，避免创建理论上的无限纸带。
- 实现 ``read_symbol``、``write_symbol``、``move_head``、``step``、``run`` 和 ``count_ones``，完成单台机器的完整运行闭环。
- 手写 BB(2) champion 状态表，验证机器可以得到 ``steps = 6``、``ones = 4`` 的经典结果。

Rust 工程化拆分
----------------
- 将早期单文件 ``main.rs`` 拆分为 Rust 工程化模块结构，避免所有逻辑堆叠在入口文件中。
- 新增 ``lib.rs`` 作为库模块统一出口，明确 ``model``、``tape``、``machine``、``generator`` 和 ``search`` 的职责边界。
- ``model`` 层负责领域模型定义，包括 ``State``、``Direction``、``Transition``、``Symbol`` 和 ``RuleKey``。
- ``tape`` 层负责无限纸带抽象，封装读写、默认 ``0`` 语义和 ``1`` 数量统计。
- ``machine`` 层负责单台图灵机执行，不参与候选机器生成和 Busy Beaver 搜索流程。
- ``generator`` 层负责枚举候选状态转移表，为后续 BB(n) 搜索提供机器来源。
- ``search`` 层负责编排 ``生成机器 -> 运行机器 -> 判断停机 -> 记录最优`` 的搜索流程。
- Rust 模块采用 ``mod``、``pub``、``use`` 和 ``crate`` 管理可见性，不采用 C++ 中 ``.h`` / ``.cpp`` 的声明实现分离模式。

BB(2) 暴力搜索器
----------------
- 新增 ``MachineGenerator``，支持根据状态数量和符号数量枚举所有候选状态转移表。
- 对于 BB(2)，生成 ``A0``、``A1``、``B0``、``B1`` 四个规则入口。
- 每条规则枚举 ``写入 0/1``、``移动 L/R``、``下一个状态 A/B/H`` 的全部组合。
- BB(2) 搜索空间为 ``12^4 = 20736`` 台机器，搜索器可以完整枚举并运行。
- 新增 ``BusyBeaverSearch``，负责执行完整搜索流程并统计总机器数、正常停机机器数、达到步数上限机器数和缺失转移规则机器数。
- 新增 ``SearchResult``，记录当前最优 ``ones``、``steps`` 和对应状态转移表。
- 搜索结果验证 BB(2) 可以得到 ``best ones = 4``、``best steps = 6``。
- 输出示例中的 BB(2) 最优转移表为等价 champion 形式，例如 ``A0 -> 1LB``、``A1 -> 1RB``、``B0 -> 1RA``、``B1 -> 1LH``。

BB(n) 参数化搜索入口
--------------------
- 搜索器从固定 BB(2) 升级为参数化 BB(n) 搜索框架。
- 支持通过命令行参数指定普通状态数量，例如 ``cargo run -- 2`` 运行 BB(2)，``cargo run -- 3`` 运行 BB(3)。
- ``State::Normal(u8)`` 替代写死的 ``A`` / ``B`` 枚举，使 ``Normal(0)`` 对应 ``A``，``Normal(1)`` 对应 ``B``，``Normal(2)`` 对应 ``C``。
- ``SearchConfig`` 支持配置 ``state_count``、``symbol_count`` 和 ``max_steps``，为后续 BB(3)、BB(4) 实验做准备。

- 状态转移表打印函数支持将状态编号格式化为 ``A``、``B``、``C`` 等人类可读名称，``H`` 表示停机状态。
- 明确同一套 BB(n) 搜索软件可以通过 ``state_count = 2`` 重新生成 BB(2)，通过 ``state_count = 3`` 搜索 BB(3)，不再为每个 n 单独写一套程序。
